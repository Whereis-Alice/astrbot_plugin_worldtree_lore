# 世界树

一个面向 AstrBot 的动态世界书插件：用关键词、适用范围或 Cron 规则激活条目，并在当前模型请求中注入相应设定、规则和背景。

它提供独立命名空间和原生 WebUI，重点解决“条目多了以后难找、难改、容易覆盖”的问题。你可以直接搜索名称、内容、标签、文件夹、关键词和适用范围，无需逐个展开配置项。

> 本项目是基于 [Zhalslar/astrbot_plugin_worldbook](https://github.com/Zhalslar/astrbot_plugin_worldbook) 思路进行的独立衍生重构，并非上游官方版本。完整致谢与许可说明见[文末](#致谢与上游项目)和 [NOTICE.md](NOTICE.md)。

## 主要特点

- 世界树主题管理台：绿色主调，背景是一棵占满整个视口的程序化世界树，侧栏以树干与枝芽组织面板；内置白昼、暗林、荧夜三套配色，也可跟随 AstrBot，并适配窄屏。
- 服务端搜索与分页：条目很多时也不需要逐个展开。
- 七种排序方式并自动分组：按优先级、条目类型、文件夹、名称、最近更新或启用状态整理长列表。
- 文件夹、标签、状态、模板筛选和内容预览：在列表中直接确认目标条目。
- 条目自带模板徽章：一眼看出它是常规、常驻、随机、日程、群聊限定还是用户限定条目。
- 选择本页与批量操作：批量启用、禁用、移动文件夹、添加/移除标签或删除。
- 安全编辑：使用修订号检查；其他页面已改过条目时，不会直接覆盖新内容。
- JSON/YAML 导入导出：兼容本插件、上游 Worldbook 以及常见世界书字段。
- 会话级固定与屏蔽：不再通过修改全局 `scope` 假装“仅当前会话生效”。
- 默认临时上下文注入：不写入聊天历史；也可按需切换到 `system_prompt`。
- 新条目默认按字面量匹配：只有明确写成 `re:<表达式>` 才会作为正则处理。
- 复制为新条目、导出所选条目、拖拽 JSON 导入，以及紧凑视图和键盘快捷键。
- 独立插件名、命令组、数据目录、Web API 和 LLM 工具名，可与上游插件同时安装。

## 运行要求

- AstrBot `>= 4.26.0, < 5`
- Python 依赖会按 [requirements.txt](requirements.txt) 安装：
  - APScheduler 3.x
  - PyYAML 6.x

最低版本设为 AstrBot 4.26.0，是因为本插件使用了该版本提供的 Plugin Pages 和 `astrbot.api.web` 接口。

## 安装与打开管理台

1. 在 AstrBot WebUI 的插件管理页面安装本仓库，或上传发布页提供的 ZIP。
2. 等待依赖安装完成，随后重载插件；必要时重启 AstrBot。
3. 打开“世界树”插件详情。
4. 点击页面入口“世界树管理台”。

管理台中：

- 左侧是一列「树干」，树冠概览、定位条目、移植与留种三块面板作为枝节挂在上面；移动端默认折叠，避免挡住条目列表。
- 树冠概览里的年轮总数与叶片标签都是筛选按钮，点一下即切到对应视图（文件夹数量只作展示）。
- 中间列表直接展示名称、启用状态、文件夹、标签、优先级、触发器数量和内容摘要。
- 点击条目主体或“编辑”即可打开编辑抽屉。
- 勾选条目或点击“选择本页”后，会出现批量工具栏。
- 导入、导出入口位于筛选区域，也支持把 JSON 文件直接拖到页面上。
- 右上角有四档主题切换（跟随 AstrBot / 白昼 / 暗林 / 荧夜），选择会记在本地浏览器；旁边还有紧凑视图和“收起全部”。

## 条目可以在哪里管理

条目并非只能在 WebUI 设置。世界树提供四种管理入口：

- **世界树管理台**：创建、搜索、查看和编辑全部字段，并支持筛选、分页、批量操作、导入和导出。这是完整管理入口。
- **管理员聊天命令**：支持查找、查看、快速添加、删除、全局开关，以及当前会话的固定、屏蔽和清理。快速添加会创建一个以名称为默认触发词的常规条目。
- **JSON/YAML 导入**：适合批量创建或迁移条目，可以选择跳过、自动重命名或覆盖同名条目。
- **可选模型工具**：开启配置后，模型可以为管理员创建待复核条目；默认关闭，且不用于完整字段编辑。

目前，文件夹、标签、优先级、概率、时长、次数、关键词模式、Cron、适用范围等完整字段的交互式修改，需要使用世界树管理台。聊天命令主要用于快速操作，详见[管理员命令](#管理员命令)。

## 为什么条目多了也容易找

原插件的配置式条目列表需要逐项展开。世界树管理台改为独立的检索界面，搜索和分页都在插件后端完成。

搜索支持同时匹配：

- 条目名称
- 注入内容
- 文件夹
- 标签
- 关键词 / 正则触发器
- 适用范围

输入多个词时采用“全部包含”的方式。例如搜索 `雾港 主线`，只返回同时包含这两个词的条目。还可以叠加启用状态、文件夹、标签和模板筛选。

除了搜索，管理台还提供这些定位手段：

- **排序与自动分组**：可选优先级由小到大 / 由大到小、条目类型、文件夹、名称、最近更新、启用状态。切换排序后，列表会生成对应的分组标题，例如“树心 · 优先级 ≤ 10”“主干 · 优先级 11–50”，或直接按模板、文件夹名分段。
- **模板徽章与模板筛选**：每个条目标出所属模板，也可以只看某一类，例如只列出全部“日程条目”。
- **可点击的树冠概览**：年轮总数卡与「启用中 / 已停用 / 日程 / 范围限定」叶片标签本身就是筛选按钮，点一下就切换视图。
- **紧凑视图与收起全部**：长列表一屏能看到更多条目；需要细读时再展开。
- **键盘快捷键**：`/` 聚焦搜索、`N` 新建条目、`Ctrl+Enter` 保存、`Esc` 关闭当前弹层。

需要以现有条目为蓝本时，用“复制为新条目”派生一份再改；需要把一部分条目交给别人时，勾选后“导出所选”即可。导入除了走按钮，也可以把 JSON 文件直接拖到页面上。

## 条目如何生效

一次普通流程是：

```text
用户消息或 Cron → 关键词/范围/概率检查 → 当前会话激活 → 按优先级和字符预算选择 → 注入本轮模型请求
```

主要字段含义如下：

| 字段 | 说明 |
| --- | --- |
| 全局启用 | 关闭后，任何会话都不会激活该条目。 |
| 名称 | 条目的唯一名称，也是管理台和命令定位条目的依据。 |
| 文件夹 | 用于分类和筛选，不影响触发逻辑。 |
| 标签 | 用于检索、筛选和批量管理，不影响触发逻辑。 |
| 优先级 | 数字越小越先注入；字符预算不足时，低优先级条目可能被跳过。 |
| 生效概率 | `0` 到 `1`；例如 `0.05` 表示 5%。 |
| 生效时长 | 激活后可持续的秒数；`0` 表示不限制时长。 |
| 最多注入次数 | 当前会话激活后最多实际注入多少次；`0` 表示不限次数。 |
| 关键词 | 每行一个；留空时只能由 Cron 或管理员“固定”命令激活。 |
| Cron | 标准五段格式：`分 时 日 月 周`。 |
| 适用范围 | 限定管理员、用户、群聊或具体会话；留空表示不限。 |
| 注入内容 | 条目生效后提供给模型参考的正文。 |

重复命中同一条目不会重新计算它的生效时长或恢复剩余次数。这修复了上游实现中重复关键词可能不断刷新生命周期的问题。

## 六种条目模板

模板只做两件事：新建条目时填入一套预设值，以及给条目一个可筛选、可排序的分类徽章。它不是六条独立的注入通道——六种模板共用同一套字段与同一套判定逻辑，所以任何模板的条目都可以再手动改成别的行为。

| 模板 | 预设优先级 | 预设关键词 | 生效时长 | 最多次数 | 典型用途 |
| --- | --- | --- | --- | --- | --- |
| 常规条目 | 50 | 空（自己填） | 180 秒 | 5 次 | 提到某个词才需要补充的设定 |
| 常驻条目 | 10 | `re:.*` | 不限 | 不限 | 世界观底层设定，每轮都想带上 |
| 随机条目 | 30 | `re:.*` | 180 秒 | 1 次 | 概率触发的彩蛋（另配生效概率） |
| 日程条目 | 80 | 空 + Cron `0 0 * * *` | 86400 秒 | 不限 | 到点自动生效的时间设定 |
| 群聊限定 | 120 | `re:.*` | 不限 | 不限 | 只在某些群生效（另配适用范围） |
| 用户限定 | 150 | `re:.*` | 不限 | 不限 | 只对某些用户生效（另配适用范围） |

由此可以解释一个常见疑问：**为什么常驻条目也要填触发方式？** 因为“常驻”正是用 `re:.*`（匹配任意消息）加上不限时长、不限次数实现的。条目只认两种激活信号——关键词命中或 Cron 窗口——所以清空关键词后，常驻条目就再也不会生效。

注意关键词要写成 `re:.*` 而不是 `.*`：默认的“字面量优先”模式会把 `.*` 当成两个普通字符来匹配。详见下一节。

在编辑器里切换模板只会改变分类，不会覆盖你已经填好的字段；确实想回到预设时，点“套用该模板默认值”。

## 关键词：字面量与正则

新建条目默认使用“字面量优先”模式：

```text
雾港
角色设定
```

以上内容按普通文本查找，`.`、`*`、`[` 等字符不会被误当作正则语法。

只有显式添加 `re:` 前缀时才使用正则：

```text
re:雾港|旧码头
re:^角色设定\s*[:：]
```

从上游 Worldbook 导入且可识别为上游格式的条目，会保留“所有关键词都按正则处理”的旧行为，避免迁移后触发语义突然改变。你可以在编辑器中将“关键词模式”改为新模式，再逐步把需要的正则补上 `re:`。

> 正则由管理员维护。复杂或灾难性回溯表达式可能拖慢匹配；普通关键词优先使用字面量模式。

## 适用范围写法

每行填写一个范围；满足任意一项即可使用该条目：

```text
admin
user:<用户 ID>
group:<群 ID>
session:<UMO>
```

为兼容旧文件，也接受直接填写旧式用户 ID、群 ID 或 UMO。新条目建议使用带前缀的明确写法。

“固定”和“屏蔽”命令只改变当前会话的临时状态，不会写回全局 `scope`：

- 固定：立即让一个允许当前会话使用的条目生效。
- 屏蔽：仅在当前会话阻止该条目。
- 插件重载后，这些会话运行态会清空。

## Cron 规则

Cron 使用标准五段表达式：

```text
0 9 * * 1-5
```

表示周一至周五每天 09:00 触发。星期字段遵循常见 crontab 约定：`0` 或 `7` 表示星期日，`1` 表示星期一。

Cron 到点后会打开一次待激活信号，由后续符合范围的模型请求接收。被当前会话临时屏蔽的条目不会抢走该信号。

## 内容占位符

注入内容支持以下安全占位符：

| 占位符 | 内容 |
| --- | --- |
| `{user_id}` | 当前发送者 ID |
| `{user_name}` | 当前发送者名称 |
| `{user}` | 名称与 ID 的组合 |
| `{time}` | 当前本地时间，格式为 `HH:MM:SS` |
| `{entry_name}` | 当前条目名称 |

未知占位符会原样保留。本插件不会执行表达式、属性访问或函数调用。

## 管理员命令

所有修改命令都使用独立的“世界树”命令组，避免与上游命令冲突。

| 命令 | 作用 |
| --- | --- |
| `世界树 帮助` | 查看简要帮助。 |
| `世界树 查找 <关键词>` | 搜索名称、内容、标签、文件夹、关键词和范围。 |
| `世界树 查看 <名称>` | 查看一个条目的完整设置和内容。 |
| `世界树 添加 <单词名称> <内容>` | 快速添加常规条目；复杂设置建议使用管理台。 |
| `世界树 删除 <名称>` | 删除全局条目。 |
| `世界树 全局开关 <名称> <开或关>` | 修改全局启用状态。 |
| `世界树 固定 <名称>` | 仅在当前会话立即激活条目。 |
| `世界树 屏蔽 <名称>` | 仅在当前会话屏蔽条目。 |
| `世界树 解除屏蔽 <名称>` | 取消当前会话屏蔽。 |
| `世界树 会话状态` | 查看当前会话的激活和屏蔽状态。 |
| `世界树 清理` | 清除当前会话的激活条目。 |
| `世界树 清理 全部` | 同时清除激活条目和临时屏蔽。 |

具体命令前缀取决于 AstrBot 的全局命令配置。

## 可选的模型写入工具

配置项“允许模型为管理员创建条目”默认关闭。

开启后，只有管理员发起的模型请求会看到独立工具：

```text
worldtree_lore_add_entry
```

插件会在请求阶段对非管理员隐藏该工具，并在工具实际执行时再次检查管理员权限。模型创建的条目会自动放入“LLM 创建”文件夹并添加同名标签，方便集中搜索和人工复核。

建议只在确实需要模型保存长期规则、偏好或摘要时开启；不要把它当作无审核的自动记忆。

## 导入、导出与迁移

### 从上游 Worldbook 迁移

1. 在上游插件中使用 `导出世界书`，取得 JSON、YAML 或 YML 文件。
2. 打开世界树管理台，点击“导入世界书”。
3. 选择同名条目策略：
   - 跳过：保留现有条目，安全性最高。
   - 自动重命名：两者都保留，导入项会变成类似 `名称 (2)`。
   - 覆盖：用导入内容替换本插件中的同名条目。
4. 导入后搜索并抽查关键词模式、适用范围和 Cron。

单个导入文件最大 2 MiB，单次最多处理 2000 个条目。文件必须使用 UTF-8 编码。

### 支持的常见字段

除本插件和上游格式外，导入器也会识别常见世界书字段，例如：

- `entries`、`world_info`
- `comment`、`name`
- `key`、`keys`、`keywords`
- `order`、`insertion_order`、`priority`
- `disable`、`enabled`
- `content`

不同世界书生态的高级语义并不完全一致。导入完成不等于行为百分之百等价，建议先备份并抽查关键条目。

### 备份

管理台可以导出 JSON 或 YAML。导出文件包含全部持久字段，不包含当前会话的激活次数、剩余时长和临时屏蔽状态。

插件只保留有限数量的服务器端临时导出文件，防止长期下载产生无上限占用；真正的备份请保存下载到的文件。

## 与上游插件同时安装

本项目不会复用上游的关键标识符：

| 类型 | 世界树 |
| --- | --- |
| 插件包名 | `astrbot_plugin_worldtree_lore` |
| 插件类 | `WorldTreeLorePlugin` |
| 命令组 | `世界树` / `worldtree` |
| Web API 前缀 | `/astrbot_plugin_worldtree_lore` |
| LLM 工具 | `worldtree_lore_add_entry` |
| 数据目录 | `astrbot_plugin_worldtree_lore` 独立目录 |

因此可以先并行安装、导入、核对，再决定是否停用旧插件。本插件不会自动读取或修改上游插件的数据。

## 插件配置

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| 单次最多注入条目数 | `6` | 按优先级选择；设为 `0` 可暂停注入。 |
| 单次最多注入字符数 | `12000` | 超出预算的低优先级条目会跳过，不会截断原文。 |
| 注入位置 | `extra_user_content` | 推荐的本轮临时用户上下文；也可选 `system_prompt`。 |
| 允许同优先级共存 | `true` | 关闭时，新激活的同优先级条目会替换旧条目。 |
| 会话运行态保留分钟数 | `1440` | 清理长时间未活动的临时会话状态。 |
| 允许模型为管理员创建条目 | `false` | 控制 `worldtree_lore_add_entry` 工具。 |

`extra_user_content` 使用临时内容部件，只参与当前请求，不写入对话历史。只有确实需要 system 层级优先级时才建议切换为 `system_prompt`。

## 常见问题

### 插件详情中没有“世界树管理台”

- 确认 AstrBot 版本不低于 4.26.0。
- 重载插件或重启 AstrBot。
- 检查插件目录中是否存在 `pages/worldtree/`。
- 查看 AstrBot 日志中是否有插件加载或依赖安装错误。

### 条目没有触发

- 确认“全局启用”已打开。
- 新模式下正则必须以 `re:` 开头。
- 检查 `scope` 是否允许当前用户、群聊或会话。
- 检查概率是否为 0、激活次数是否已用完、时长是否已过期。
- 只有 Cron、没有关键词的条目，需要等待下一次有效调度信号。

### 保存时提示条目库已被更新

另一个管理台页面、命令或模型工具已先修改条目。刷新列表并重新打开条目，确认最新内容后再保存。该提示用于避免静默覆盖。

### 导入后正则行为与新条目不同

可识别的上游条目会使用“兼容旧世界书：全部按正则”模式。新建条目则默认按字面量匹配。这是为了同时保证迁移兼容和新配置安全。

## 已修复或改进的上游问题

- 重复关键词命中不再重置已激活条目的时长和剩余次数。
- 当前会话固定/屏蔽不再修改全局 `scope`。
- 新关键词不再默认作为正则，减少误匹配和无效表达式。
- 条目不再依赖逐项展开查找，改用搜索、筛选、预览和分页。
- 多页面编辑增加修订冲突检查，减少后保存的旧页面覆盖新修改。
- 调度星期字段按标准 crontab 语义转换。
- 被某个会话屏蔽的 Cron 条目不会消耗其他会话可接收的待激活信号。
- 导入大小、条目数量、字段长度、注入条数和字符预算均有限制。
- 会话运行态不持久化，重载后不会带着陈旧的剩余次数或屏蔽状态。
- 删除确认改为页内对话框，不再依赖被插件页沙箱禁用的原生 `window.confirm()`。
- 深色模式下的开关控件与图例文字补足对比度。
- 编辑抽屉在小屏上可以正常滚动到底，不再溢出裁切。
- 只有一页结果时不再保留空白的分页区域；分页按钮补上 `aria-current` 与可读标签。
- 移动端工具栏按钮不再换行错位，导入弹窗打开后焦点会移入对话框。

## 数据与安全说明

- 世界书内容会发送给当前配置的模型提供商，请勿写入不希望提供商看到的秘密。
- WebUI 修改接口依赖 AstrBot 插件页面的鉴权与桥接，不额外开放匿名管理页面。
- JSON/YAML 导入使用安全解析，并限制文件大小与条目数量。
- 正则仍由管理员负责；优先使用普通字面量关键词。
- 删除操作会要求确认，但管理台内没有回收站；删除前建议先导出备份。
